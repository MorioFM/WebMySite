# Чек-лист проверки адаптивности интерфейса (responsive-check)

Настоящий навык регламентирует порядок проведения аудита адаптивности, доступности и корректного поведения веб-интерфейса на различных устройствах и разрешениях экрана.

---

## 1. Базовые разрешения (Брейкпоинты)

Проверка проводится минимум на 4 целевых ширинах экрана:
1. **360 px (Mobile Small)**: базовый мобильный телефон (вертикальная ориентация).
2. **768 px (Tablet Portrait)**: планшеты и переходная точка переключения навигации.
3. **1280 px (Desktop / Laptop)**: стандартные ноутбуки и десктопные мониторы.
4. **1920 px (Large Screen / Full HD)**: широкие мониторы высокого разрешения.

---

## 2. Критерии чек-листа

### А. Отсутствие горизонтального переполнения (No Horizontal Scroll)
- [ ] `document.documentElement.scrollWidth === window.innerWidth` (или разница не превышает 1 px на скроллбар).
- [ ] Ни один дочерний элемент (кроме контейнеров с преднамеренным `overflow-x: auto`, таких как широкие таблицы) не выходит за пределы правого края экрана (`rect.right <= window.innerWidth`).
- [ ] Все изображения и медиа имеют `max-width: 100%` и не распирают родительские блоки.
- [ ] Длинные текстовые метки и заголовки не ломают сетку при минимальной ширине экрана.

### Б. Шапка и навигация
- [ ] **Мобильный режим (< 768 px)**:
  - Основное меню скрыто по умолчанию;
  - Кнопка-гамбургер (`.burger`) видна и имеет контрастный вид;
  - Клик по бургеру открывает выпадающее/выезжающее меню, выставляется `aria-expanded="true"`;
  - Клик по пункту меню выполняет плавный переход к якорной секции и автоматически закрывает меню;
  - Клик вне открытого меню закрывает его.
- [ ] **Десктопный режим ($\ge$ 768 px)**:
  - Бургер скрыт (`display: none`);
  - Навигационное меню отображается горизонтально в потоке шапки;
  - Активный раздел подсвечивается при скролле (через `IntersectionObserver`).

### В. Сенсорные зоны и доступность (WCAG Touch Targets)
- [ ] Интерактивные элементы управления (кнопки, переключатель темы, бургер, кнопка закрытия модального окна) имеют минимальный физический размер сенсорной зоны не менее **44 × 44 px** (WCAG 2.5.5 / 2.5.8).
- [ ] Для всех интерактивных элементов настроен видимый индикатор клавиатурного фокуса (`:focus-visible`).
- [ ] У изображений присутствуют осмысленные атрибуты `alt`.

### Г. Модальные окна
- [ ] При открытии модального окна на экране 360 px его ширина не превышает ширину экрана с учётом боковых отступов.
- [ ] Внутренний скролл модального окна работает независимо, скролл подлежащей страницы (`body`) блокируется (`overflow: hidden`).
- [ ] Окно закрывается:
  - Кнопкой закрытия (крестик);
  - Нажатием клавиши `Escape`;
  - Кликом по подложке (оверлею).
- [ ] Реализована фокус-ловушка (`trapFocus`): клавиша `Tab` не уводит фокус на скрытые за оверлеем элементы.

### Д. Цветовые темы и читаемость
- [ ] Контрастность текста в обеих темах (светлая и тёмная) удовлетворяет требованиям WCAG AA (не менее 4.5:1 для основного текста).
- [ ] Переключатель тем корректно переключает атрибут темы (`data-theme`) и сохраняет выбор пользователя в `localStorage`.
- [ ] Учитывается системная настройка через медиазапрос `prefers-color-scheme`.
- [ ] Учитывается предпочтение пользователя по снижению движения `prefers-reduced-motion`.

---

## 3. Методы автоматизации тестирования

1. **CDP (Chrome DevTools Protocol)**:
   - Эмуляция устройств через `Emulation.setDeviceMetricsOverride` с точными размерами ширины и высоты.
   - Запуск JS-проверок `getBoundingClientRect()` и `scrollWidth` для каждого элемента DOM.
   - Фиксация визуальных скриншотов через `Page.captureScreenshot`.
2. **Playwright / Headless Browser**:
   - Автоматизация кликов по интерактивным элементам, верификация классов состояния и снятие скриншотов брейкпоинтов.
